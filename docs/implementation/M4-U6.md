## Dependencies and current state

- M4-U3 provides persisted deterministic comparison snapshots and effective read-time staleness detection. M4-U4 exposes factual comparison and stale state in the browser.
- M4-U5 provides the project-scoped, read-only comparison and quote evidence tools. The existing Sourcing Analyst has supplier tools, a shared successful-call budget, model-turn limits, retry behavior, and `AIRun` tracing.
- The analysis response will not be persisted. The existing `AIRun.input_hash` can bind a run to canonical input containing the snapshot identity and revision inputs; existing trace facilities record the run steps without a new schema or migration.

## Reviewed implementation plan

1. Add a versioned `TradeoffAnalysis` structured output contract and a comparison analyst task. The contract is limited to supplier summaries, key tradeoffs, important unknowns, and important conflicts. Do not add `SuggestedSupplierResult`, a suggested supplier ID, ranking, recommendation, or preferred-supplier action.
2. Add a session-scoped API operation that generates and returns analysis for the latest comparison. Before model invocation, require an existing, current snapshot. Derive immutable `AnalystToolContext` permitted supplier and quote ID sets from the suppliers and quotes participating in that snapshot. Do not let model arguments broaden the scope.
3. Reuse the existing analyst tool loop, provider retry and structured-output repair behavior, and configurable limits (four model turns and six successful tool calls by default). Permit only the existing read-only comparison, supplier, supplier-evidence, and quote-evidence tools. Do not introduce a second retry loop or state-changing tool.
4. Validate the final result against its schema, allowed supplier/quote/evidence IDs and references, snapshot and revision freshness, and other hard contract rules. Require analysis to preserve deterministic Unknown and Conflict states and reject numeric supplier scores through contract-level checks where explicit. Evaluate unsupported or invented narrative claims with groundedness evals; do not build a new semantic validator.
5. Include the comparison snapshot identity and revision inputs in the canonical `AIRun` input hash and associate ordered trace steps with that run using existing facilities. Recheck current snapshot identity and effective freshness before returning the result. If inputs change during the run, return a recoverable stale-input failure instead of presenting the output as current. Record provider, validation, and limit failures as recoverable run outcomes. Return the successful analysis only in the API response; do not persist its narrative.

## Acceptance criteria

- An absent or stale comparison does not start a model run. Regenerating the comparison supplies the new snapshot to the next run.
- Tool permissions contain only IDs from the current snapshot, and all tool calls remain session/project scoped and read-only.
- A response is returned only while its bound snapshot and revision inputs remain current. Unknown, Conflict, and required-failure facts are represented without fabricated scores or unsupported factual references.
- The run records model turns, successful tool calls, retries, failures, and snapshot/revision identity through existing facilities. Provider, invalid-output, budget, and changed-input failures can be retried by the caller.
- No analysis-result persistence, database migration, frontend change, or Suggested Supplier behavior is added.
