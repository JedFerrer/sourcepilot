# M3-U1 — Quote Persistence and Provenance Domain

## Status

`COMMITTED`

## Objective

Establish persisted quote and field-level provenance records for one quote per
shortlisted supplier in a project. No quote API or UI is part of this unit.

## Dependencies and existing state

M2-U7 is committed and persists shortlist approval using the project's stage.
`ProjectSupplier` identifies the project candidate pair and `shortlisted` state.
The existing `brief_revision` starts at zero and advances on meaningful edits;
its approval does not advance the revision. No quote tables exist yet.

## Approved implementation plan

1. Add `Quote` and `QuoteValue` persistence models and an Alembic migration.
   Allow one quote per project/supplier pair and require an existing candidate
   pair. Preserve quote records when a candidate would otherwise be deleted.
2. Add a small internal creation operation that checks the candidate is
   currently shortlisted. Do not restrict creation to an exact project stage;
   workflow-stage permission belongs to the later quote application/API slice.
3. Define `MANUAL`/`PDF` entry types, `PROCESSING`/`NEEDS_REVIEW`/`CONFIRMED`/
   `FAILED` local statuses, and `AI_EXTRACTED`/`USER_CORRECTED`/`USER_ENTERED`
   current origins. No quote row represents `Not Added`.
4. Store separate current and optional AI-extracted field values, with one
   record per field key. Preserve the AI value when a current value is
   corrected; manually entered values have no AI value. A domain read rule
   exposes current values as authoritative only for confirmed quotes.
5. Store the internal quote revision in `quotes.revision`, initially zero,
   matching the existing Brief revision convention. Later revision increments
   and confirmation actions belong to M3-U9 and M3-U2/M3-U9 respectively.

## Acceptance criteria

- A quote links to an existing project/supplier candidate and is created only
  while that candidate is shortlisted, without an exact project-stage guard.
- AI-extracted and current values remain distinct, and origin is explicit.
- Confirmed current values are authoritative; unconfirmed values are not.
- One quote per project/supplier pair and one value per quote/field key.

## Implementation results

Added `Quote`/`QuoteValue` tables, ORM models, quote enums and provenance
rules, an internal shortlisted-candidate creation operation, and a
confirmed-only current-value read rule. Quotes retain direct project and
supplier foreign keys and a unique project/supplier pair. The creation
operation checks that the project candidate exists and is shortlisted. M2
rediscovery may remove that candidate while retaining the quote and its
values; deleting the owning project still cleans up its quote. A database
trigger prevents changes or clearing of a previously stored AI-extracted
value while allowing corrections to the current value and origin. Creation
has no exact project-stage guard. Revision starts at zero, matching
`brief_revision`.

## Review findings

1. The quote-to-`ProjectSupplier` foreign key blocked M2 rediscovery when a
   quoted candidate disappeared. Removed that composite foreign key, retained
   direct project/supplier linkage and uniqueness, and kept the shortlisted
   candidate check at creation. Integration coverage confirms rediscovery
   removes the candidate and leaves the quote and its value intact.
2. A correction could overwrite or clear a stored `ai_extracted_value`.
   Added a database update guard and negative tests for both attempts. The
   correction round-trip still confirms the extracted value is preserved.

Both findings are fixed and verified locally. Re-review found no remaining
findings: the rediscovery integration test preserves the quote after candidate
removal, and the database guard rejects clearing or changing stored AI values.
