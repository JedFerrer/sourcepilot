## Approved scope

- Official Responses client wrapper with lazy, required OpenAI key/model configuration and `store=false`.
- Prompt-version identifiers, structured output helper, bounded retry behavior, and mockable provider calls.
- `AIRun` persistence, including latency/tokens/status/validation data and nullable model-turn/tool-call counts.
- A no-op optional Langfuse adapter boundary.
- Manual, opt-in development smoke operation using `foundation-smoke-v1`.

## Explicitly out of scope

- Product prompts, AI product APIs/UI, brief/clarification/quote capability logic, and Sourcing Analyst tools.
- Live Langfuse integration, agent loops, generalized orchestration, or frontend work.
- Any automated or CI OpenAI invocation.

## Approved implementation plan

1. Add the official model SDK and a narrow injectable Responses wrapper.
2. Add one `AIRun` migration and application-owned lifecycle recording.
3. Run structured operations through at most two total provider invocations. A second call may be a provider retry or schema repair; no third call is permitted.
4. Add model-client fakes, persistence coverage, and the manual-only CLI smoke command.

## Acceptance criteria

- [x] A development AI smoke operation creates one AIRun.
- [x] Success and failure persist their terminal states.
- [x] One schema repair retry can be tested while all paths remain capped at two total calls.
- [x] The system works without Langfuse.
- [x] Provider calls are mockable and automated tests/CI never call OpenAI.
