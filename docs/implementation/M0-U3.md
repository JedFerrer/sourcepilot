## Objective

Implement fixed-lifetime, anonymous demo sessions that isolate every project's
data to the current valid session.

M0-U2 — Persistence and Migration Foundation.

## Approved scope

- Server-generated opaque tokens delivered only in an HttpOnly demo-session
  cookie.
- Fixed, configurable 24-hour session expiry, automatic creation/reuse, and
  expired-session enforcement.
- `POST /demo-session` and automatic frontend bootstrap.
- One project ownership lookup that takes an already-resolved, unexpired
  `DemoSession` plus a project ID and scopes the lookup to that session.
- Backend, real-PostgreSQL integration, frontend, and browser QA coverage.

## Explicitly out of scope

- Project creation, list/read/rename APIs or UI, dashboard, and workspace
  behavior (M0-U4).
- User accounts, authentication frameworks, RBAC, enterprise identity, CORS
  expansion, shared frontend API conventions, AI infrastructure, and later
  domain models.
- Session-data cleanup and any migration beyond the committed M0-U2 foundation.

## Approved implementation plan

1. Add validated `DEMO_SESSION_TTL_SECONDS` and
   `DEMO_SESSION_COOKIE_SECURE` environment configuration using the existing
   direct environment-variable approach, with local and production guidance.
2. Add a focused session service that generates secure opaque tokens, creates
   fixed-expiry sessions, resolves only unexpired sessions, and records
   `last_seen_at` without renewing expiry.
3. Add `POST /demo-session`, issuing a host-only `HttpOnly`, `SameSite=Lax`
   cookie only when a new session is created. Valid reuse leaves the existing
   cookie unchanged.
4. Add only the resolved-session project ownership lookup; callers may not
   authorize a project query by passing a `demo_session_id`.
5. Add idempotent browser bootstrap, focused tests, documentation, and required
   Browser QA without starting M0-U4 project functionality.

## Acceptance criteria

- [x] A first visitor receives a session cookie.
- [x] A project lookup requires the current resolved session and can retrieve
  only that session's project.
- [x] Another session cannot access a project by its ID alone.
- [x] An expired session fails resolution and cannot access its old project.
- [x] Session reuse neither renews `expires_at` nor refreshes a full-TTL cookie.
