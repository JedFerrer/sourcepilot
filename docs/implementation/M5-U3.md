- Launch the test API and production-built web server on dedicated loopback ports without existing-server reuse. Keep specs outside Vitest discovery; lint/typecheck support code.
- Require explicit E2E_DATABASE_URL, DATABASE_URL, and TEST_DATABASE_URL. Preserve protected URLs before reconfiguring the application.

## Review findings

Review identified two approved findings. Both have been addressed within M5-U3;
the unit remains `IN_REVIEW` for review of these fixes.

- **P1 — destructive reset connection identity:** the original guard checked only
  the connected database name, disposed that connection, and reset through new
  connections. An inherited libpq routing setting could redirect the connection.
  The fix rejects the entire inherited `PG*` namespace, including `PGHOSTADDR`,
  service/service-file settings, options, multi-host settings, and future settings;
  rejects URL query overrides; requires explicit credentials; and pins the resolved
  loopback address and port. It positively checks the connected libpq database,
  address, port, and user plus the server-reported database/user. Validation,
  prerequisite deletion, Alembic downgrade/upgrade, and catalog seeding use the same
  open connection and transaction. A test-only Alembic environment requires that
  connection and cannot create a replacement. Production migration files are unchanged.
  Launcher/reset regressions prove overrides, unavailable/disagreeing identity,
  protected/ambiguous targets, and failed guards stop before reset/writes; they also
  prove the successful reset boundary receives the validated connection.
- **P2 — session credentials in failure artifacts:** CI previously uploaded raw
  Playwright reports/traces/attachments. Each stage now builds a separately sanitized
  `diagnostics.zip`; upload is gated on sanitizer success and restricted to that ZIP.
  The sanitizer processes nested trace ZIPs, compressed HTML report data, raw and
  structured Cookie/Set-Cookie headers, browser cookie storage, session-token fields,
  JSON-encoded results, encoded buffers/attachments, and raw/URL/base64/hex/escaped
  token representations. Opaque binary attachments are redacted; credential-free
  screenshots, stage errors, timing, network status, steps, and reports remain.
  A failed sanitizer removes any prior upload bundle. A real Playwright failure with
  a known dummy token verifies that the actual upload ZIP and its decompressed/decoded
  contents contain no token. Its trace JSON remains parseable and its sanitized HTML
  report renders the failing stage and steps. Synthetic artifact tests also cover
  encoded/nested representations and fail-closed malformed report data.
