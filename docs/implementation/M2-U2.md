## Objective

Return up to five relevant synthetic supplier candidates for an approved Brief.

## Approved scope and implementation plan

1. Retrieve catalog suppliers by normalized product category, including the
   current cosmetic-bag demo aliases. Return no unrelated categories.
2. Rank category matches deterministically using requested material and
   capability matches, certification availability, general MOQ compatibility,
   and stable name/ID tie breakers. Keep useful near matches; do not expose a
   numeric supplier score or evaluate requirement states.
3. Add an application service for the current approved Brief and a transient
   `POST /projects/{id}/suppliers/discover` response with Brief revision and up
   to five supplier catalog snapshots. Reuse demo-session project ownership.
4. Add unit, repository, and API tests for category filtering, aliases, stable
   ordering, near matches, unknown and conflicting facts, approval gating,
   and session isolation.

## Explicitly out of scope

Candidate persistence, requirement evaluation, shortlist/review state,
staleness, evidence viewer, frontend UI, AI calls, migrations, and new
dependencies. M2-U4 owns persisted candidates and evaluations.

## Acceptance criteria

- The approved cosmetic-travel-bag demo Brief returns five useful candidates.
- Unrelated categories are excluded; near matches remain eligible.
- Results and tie breaks are deterministic; fewer than five are returned when
  the catalog has fewer relevant suppliers.
- Missing facts are not treated as failures, and conflicting evidence is not
  resolved during retrieval.
- Unapproved Briefs are rejected, and projects remain session isolated.
