## Approved implementation plan

### Versioned contracts, runtime, and tracing

- Add a versioned `ComparisonAdvice` structured contract containing `analysis: TradeoffAnalysis` and `suggestion: SuggestedSupplierResult`. The suggestion contains nullable `supplier_id`, structured supporting reasons, tradeoffs, uncertainties, and evidence IDs, reusing `AnalysisPoint`.
- Introduce a dedicated combined prompt with version `comparison-advice-v1`. Preserve M4-U6's `tradeoff-analysis-v1` prompt, tradeoff-only contract, API response, and behavior.
- Add `POST /projects/{project_id}/comparison/advice`, accepting `snapshot_id` and returning `{run_id, snapshot_id, analysis, suggestion}`.
- Reuse M4-U6's bounded runtime through a narrow shared runner: snapshot-derived read-only permissions, existing model/tool budgets, provider retry, and one structured-output repair retry.
- Record the combined run distinctly as `AIRun.operation = "comparison_advice"`. Store prompt version, model, canonical input hash derived from combined instructions plus snapshot identity, brief revision, quote revision inputs, and comparison payload; record validation outcome, model-turn count, successful tool-call count, and terminal status.
- Associate existing ordered trace steps with that AIRun for model calls, tools, retries, validation, limits, freshness checks, and final outcomes. Preserve M4-U6's operation metadata and tracing behavior.
- Return `409 COMPARISON_STALE` for freshness failures before invocation, during execution, or at the final recheck. Freshness failure takes precedence over another terminal failure.
- An initially absent comparison returns `404 COMPARISON_NOT_FOUND`; current-input provider, validation, or budget failures return recoverable `503 COMPARISON_ADVICE_UNAVAILABLE`.
- Keep advice response-only. Add no persistence schema, migrations, dependencies, or infrastructure.

### Structural validation

- Before invocation and returning, revalidate current shortlist membership and bound snapshot supplier/quote scope. Add no shortlist revisions or new staleness infrastructure.
- Validate supplier, requirement, quote-field, and evidence references and ownership against the bound comparison.
- Check contradictions through structured references and deterministic states only. Add no deterministic prose parser; preserve existing M4-U6 validation behavior.
- Require supporting reasons for a selected supplier and an explanation in uncertainties for a null result.
- Require structured tradeoff references for the suggested supplier's known required failures and uncertainty references for its required Unknown/Conflict findings. A supplier with a required failure may be suggested only with explicit disclosure; do not impose an automatic exclusion policy.
- Validate top-level evidence IDs and coverage of point citations. Empty evidence remains valid for claims grounded in confirmed manual values or deterministic facts.
- Use prompts and produced-output evals to assess factual wording, explicit failure disclosure, corrected-value provenance, uncertainty, unsupported recommendations, and invented scores.

### Shared Comparison UI

- Reuse existing Analyze Comparison controls and tradeoff rendering wherever present. If still absent from this checkout at implementation time, add them once within the existing Comparison screen and extend that same UI with suggestion display.
- Use one user-triggered combined request. Display Suggested Supplier to Investigate First, supporting reasons, tradeoffs, uncertainties, and inspectable sources.
- Render null as No supplier suggested yet, with its explanation. Distinguish loading, error, retry, and outdated states.
- Bind advice to snapshot identity and request generation. Invalidate on input refresh or regeneration; discard late responses after replacement, project change, or unmount.
- Recheck freshness after the run and on browser focus. Hide current advice when verification fails; detected freshness failures follow `COMPARISON_STALE`.
- Keep results in memory. Add no preferred-supplier action or Decision-stage behavior.
