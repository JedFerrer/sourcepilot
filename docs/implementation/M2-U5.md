## Approved implementation plan

1. Add an immutable application-created context with stable demo-session and
   project IDs, immutable permitted supplier IDs, and a configurable positive
   maximum successful tool-call count (default 6). Keep mutable count and trace
   state separate from the context.
2. Add typed `get_supplier_snapshot` and `get_supplier_evidence` read-only
   operations. Revalidate active session, project ownership, immutable allowed
   IDs, supplier existence, and current project candidate membership on each
   call. IDs outside the allowed set return `NOT_ALLOWED` without revealing
   existence; a deleted allowed supplier returns `NOT_FOUND`; a still-existing
   removed candidate returns `NOT_ALLOWED`.
3. Return current supplier facts and evaluations with explicit `CURRENT`,
   `STALE`, or `ABSENT` evaluation availability. Suppress stale findings and
   include both revisions for stale output. Return typed catalog evidence with
   optional claim-key filtering.
4. Record structured runtime tool events and increment the reusable counter
   only for successful calls. Block calls at the configured maximum.

## Explicitly out of scope

Agent loop, model turns, `FAILED_LIMIT_REACHED`, AIRun step persistence,
supplier explanations, API or browser changes, quote data, write tools, and
new dependencies.

## Acceptance criteria

- Current-project suppliers only, with cross-project and cross-session IDs
  rejected and no existence leak for IDs outside the immutable permitted set.
- Revalidation detects candidate removal and underlying supplier deletion
  after context creation.
- Typed current, stale, and absent snapshot states; typed evidence output.
- Calls traceable; only successful calls consume the configurable budget.
- Tool invocations do not mutate application state.

## Review findings

P2 — Resolved on 2026-09-25. `populate_existing` in the analyst tool reads
could overwrite pending edits on identity-mapped `Project`, `Supplier`, and
`ProjectSupplier` objects. The tools now select persisted columns under
`no_autoflush`, leaving the caller's pending ORM state intact. The new
PostgreSQL regression covers pending edits on all three models across both
successful and denied calls. It confirms that output and access checks use
persisted state, including a session expiry committed between calls.
