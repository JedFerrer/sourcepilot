## Approved implementation plan

1. Allow PDF confirmation only through `NEEDS_REVIEW` → `CONFIRMED`. Initial confirmation leaves revision at zero and preserves extraction, evidence, current values, and origins.
2. Allow edits to confirmed PDF and manual quotes. Increment revision once per request only when at least one normalized current value changes, including a change to or from Unknown. Equivalent values and notes-only edits do not increment it. Preserve PDF correction-origin rules and `USER_ENTERED` manual origins.
3. Enforce one active document per PDF Quote. Reads, retry, and processing use only that document. Backfill the existing canonical document only when unambiguous; fail migration on missing or ambiguous PDF document data.
4. Derive `STALE_PROCESSING` from persisted processing metadata. With the configurable default threshold of 600 seconds, an attempt is current at exactly 600 seconds and stale only after that boundary.
5. Offer retry only for stale processing. For `FAILED` PDFs, offer retry, clearer-PDF replacement, and manual fallback. Under locks, retry or replacement persists and commits the active-document and attempt transition before scheduling exactly one worker. Repeated or concurrent requests that observe the current attempt neither create another Quote nor schedule another worker.
6. Manual fallback atomically deactivates the failed PDF, replaces any unconfirmed PDF QuoteValues with normalized `USER_ENTERED` values, and removes their QuoteFieldEvidence associations. Change the existing Quote to the existing `MANUAL` entry type and reuse the M3-U2 draft editing and manual confirmation lifecycle. Retain the inactive PDF and blocks as stored provenance; introduce no fallback-specific quote state.
7. Before any background write or finalization, lock and verify the active document ID, attempt number, PDF entry type, and eligible quote/document states. Old workers cannot alter a replacement's draft, a manual fallback, or a confirmed quote.

## Acceptance criteria and tests

- PDF confirmation is user initiated from `NEEDS_REVIEW`; no processing or failed quote can be confirmed.
- Confirmed PDF and manual quote revisions change once per request only for changed normalized current values.
- Exactly one active document belongs to a PDF Quote; migration rejects ambiguous existing data.
- Stale processing starts strictly after the configured threshold; failed and stale retry are idempotent.
- Failed PDF replacement and manual fallback preserve inactive PDF provenance and reject late worker writes.
- Test API ownership and workflow guards, provenance and origins, concurrent retry/replacement, late completion, migration, frontend confirmation and recovery, and the browser-visible paths.
- Run backend tests and extraction evals, migration checks, frontend tests, type checks, and lint.

## Explicitly out of scope

Comparison snapshot/staleness implementation (M4), fallback-specific quote states, durable queues or new infrastructure, and replacement/manual fallback for `STALE_PROCESSING`.

The revision advances once for a changed normalized value; equivalent money amounts, normalized currency, and notes-only edits do not advance it. PDF correction origins and source evidence remain separate from current values.
- A migration adds the active-document marker and partial unique index. Its backfill accepts exactly one existing document per PDF quote and aborts on missing or multiple documents. Quote reads and processing select the active document.
- A read-only check of the configured application database found zero PDF quotes with missing or multiple documents and zero manual quotes with documents. No application database migration was run during this implementation step.
- Staleness is derived from persisted attempt metadata with a configurable 600-second default and a strict `>` boundary. Failed and stale attempts can be retried on the same document. Only failed PDFs can be replaced or converted to a manual draft. Retry and replacement commit their transitions before one background task is scheduled; duplicate active requests schedule none.
- Manual fallback keeps the Quote ID, changes the entry type to `MANUAL`, replaces unconfirmed values with `USER_ENTERED` values, removes evidence associations, and retains the inactive PDF and blocks. Parsing, extraction, and finalization check the active document, attempt, and quote eligibility so late workers cannot mutate a replacement, fallback, or confirmed quote.

## Approved review finding fixes (2026-09-28)

- Background tasks now carry the committed document ID and exact attempt number. Startup, parsing, extraction, AIRun commits, and finalization retain and verify that identity. A queued old attempt exits without adopting a later retry.
- The initial active `PROCESSING` attempt rejects premature retry. Only `FAILED` or effective `STALE_PROCESSING` creates a new attempt; duplicate requests observing an active retry return the existing attempt without another worker.
- The extraction session guards each AIRun commit under the same quote/document attempt locks used by PDF processing. A retry during model work cannot update its old trace or final draft. The shared structured-AI and tracing layer was not changed.
- Added regressions for premature initial retry, duplicate retry scheduling, delayed old-worker startup after a stale retry, and retry during extraction. Existing replacement, fallback, provenance, revision, and active-document cases remain in the backend suite.
