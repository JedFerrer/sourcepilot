Mapping the five historically reported failures
1–3. tests/test_eval_live.py::test_all_valid_adapters_use_real_runtime_and_scoped_tools
     [comparison-meaningful-tradeoff], [comparison-required-failure],
     [comparison-unknown-and-conflict]
The synchronous test fixture's outer transaction owns the connection. A Session
commit only releases its create_savepoint savepoint; it does not publish those
rows. The approved comparison entry point correctly opens a separately owned
connection, which cannot see the fixtures. Real authorization therefore returns
NOT_ALLOWED, surfaced as COMPARISON_NOT_FOUND. This is a fixture/caller-boundary
mismatch, not evidence of a committed-data HTTP production defect.
Correction: the test-local adapter wrapper creates the comparison/suggestion
fixtures and invokes the real adapter/runtime/tools on one owned async connection
inside an external transaction. A savepoint-bound AsyncSession permits normal
runtime commits while the outer transaction always rolls back. Trace relationships
needed by classification are loaded before closure. Other adapters retain their
original fixture. Production code is not taught to see uncommitted test rows.
New checks verify all table row counts remain unchanged after successful comparison
and suggestion runs, no AIRun escapes rollback, and stale rejection leaves no
owner/project/run rows. Existing real scope/authorization and HTTP recovery tests
remain intact. These adapter tests do not claim to test the HTTP connection
boundary; the API/deadline/recovery suites do that separately.

4. tests/test_comparison_transport.py::test_sdk_attempt_cancels_transport_and_never_retries[headers]
The historical traceback locates exhaustion after client construction, before
transport entry, followed by incomplete cleanup. The test mixed a 0.9-second
work allowance with SDK/client fixture construction. Its fake SDK factory also
discarded the application's HTTP client and created a second untracked client.
Two natural Linux suite-order attempts each passed all 1,459 cases through the
header test. The second retained the full collected suite and stopped explicitly
after header teardown; neither is a full-suite pass. Measured HTTP construction
was about 0.24/0.05 ms and SDK construction about 0.15 ms in that second attempt.
A controlled one-second constructor delay reproduced the pre-header deadline
failure with the original test. This experiment intentionally fails and is not a
regression pass. The exact historical host-delay trigger remains unproven. The
recorded GC observations do not establish a causal link to that historical stall.
Admission exhaustion is not the cause of this direct _invoke_comparison test:
it does not acquire an admission owner. No production resource leak or persistent
test-order mutation was established. The discarded test client is a confirmed
fixture ownership flaw, not proof of the historical delay's cause.
Correction: prepare one in-process SDK/HTTP fixture before starting this transport
test's unchanged clock, and have both factories return that same owned client.
Preserve the 1-second total, 50-ms attempt, 100-ms cleanup allowance, exactly-one-
request assertion, exact cancellation phase, closed-client assertions and no
surviving async tasks. A separate construction-expiry regression verifies that
request-time construction still consumes the original budget and prevents any
transport request after expiry. Production construction remains inside its budget.
