# M3-U3 — Document Storage and PDF Validation

## Status

`READY_TO_COMMIT`

The human approved the revised plan with two upload-boundary and regression-test clarifications. This unit follows the Full Flow.

## Objective

Safely accept and store original PDF quotations for shortlisted suppliers, with validated metadata and session ownership. This is an API-only upload slice; parsing, extraction, and confirmation follow in later units.

## Dependencies and existing state

M3-U1 and M3-U2 are committed. `Quote` enforces one project/supplier pair in the database, has PDF/PROCESSING values, and the API locks the project row for manual quote creation. The Quotes screen currently renders all persisted quotes as normalized-value reviews.

## Approved implementation plan

1. Add `DocumentStorage`, local filesystem storage as the development default, and a minimal S3-compatible adapter. Generate an opaque key for each upload; never use a client filename as a path. Configure the storage backend, local directory or S3 bucket/optional endpoint/region, exact file and page limits, and PDF inspection timeout. Add PyMuPDF, `python-multipart`, and boto3 with lockfile updates; add no bucket or deployment infrastructure.
2. Bound the entire HTTP request body before or during multipart parsing, including when `Content-Length` is absent, with a documented allowance for multipart framing. Independently read the file in bounded chunks and reject byte 10,000,001: the approved 10 MB default means exactly 10,000,000 bytes. Use a private temporary file, validate `.pdf` extension and `%PDF-` bytes, and run PyMuPDF open and page-count inspection in a killable child process with a configurable 10-second timeout. Reject unreadable/encrypted and over-15-page PDFs; always close/unlink temporary files. Text extraction and image-only detection belong to M3-U4.
3. Add `QuoteDocument` with a minimal relationship to `Quote` and a migration. Successful upload creates one unconfirmed PDF quote (`PROCESSING`, revision 0, no `QuoteValue` rows) and one document (`PROCESSING`, attempts 0, null start/completion/error), with key, display-safe original filename, SHA-256, and page count.
4. Add session-scoped `POST /projects/{id}/quotes/upload` with multipart `supplier_id` and `file`. Require the Quotes stage and current shortlist. Return safe quote/document metadata without storage key or path. Distinguish the same-file hash conflict from an existing different PDF/manual quote. Serialize creation using the existing project-row lock and enforce the one-active-quote invariant with the existing database uniqueness constraint. No replacement.
5. Persist Quote and QuoteDocument in one database transaction. Each upload owns only its generated key. Clean local partial writes; on confirmed database rollback, compensate by deleting the uploaded object. Record cleanup failure. On uncertain commit outcome, preserve the object and record the uncertainty; do not claim cross-system atomicity or add recovery infrastructure.
6. Make a narrow Quotes-screen change: for a PDF `PROCESSING` quote, display that the PDF is uploaded and awaiting extraction, with no normalized-value review or confirmation controls. Add no upload control.

## Acceptance criteria

- Valid PDF stores unchanged with correct metadata, safe key, session ownership, and unconfirmed quote/document state.
- Invalid extension/header, unreadable/encrypted PDF, oversized request/file, page-limit breach, and parser timeout reject without persisted rows or temporary files.
- Same-file and different-existing-quote conflicts are distinct; concurrent requests cannot create two active quotes.
- Confirm remains unavailable during PDF `PROCESSING`; manual quote behavior remains intact.
