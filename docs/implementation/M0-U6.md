## Approved scope

- A common API error envelope that preserves existing HTTP, session, and authorization semantics.
- One small frontend API client and recoverable error states for the current session, health, and project screens.
- Reusable backend test fixtures/factories and web API-response test helpers.
- Explicit CI lint, typecheck, test, and build jobs.

## Explicitly out of scope

- Domain behavior, migrations, dependencies, AI capabilities, workflow progression, new routes, and production test hooks.
- New session authorization behavior; foreign projects remain indistinguishable from missing projects.

## Approved implementation plan

1. Normalize existing 401, 404, and 422 errors and generic unhandled 500 failures into a stable envelope without changing their status or authorization behavior.
2. Add a typed, same-origin frontend request helper and migrate all current direct API calls to it.
3. Add contextual recovery states and retry actions without duplicating backend business rules.
4. Extract focused reusable test support and split CI into explicit quality/test stages while retaining build validation.

  stale project-load response to update state after a newer `projectId` load or
  retry began. The effect now invalidates its request during cleanup, and the
  success and error paths only update state for the current request.

  first after the workspace switches, and project A resolving last without
  replacing project B.

  suite (5 files, 16 tests passed); web lint and strict TypeScript check passed.
