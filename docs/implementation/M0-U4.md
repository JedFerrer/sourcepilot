## Dependencies

M0-U3 — Anonymous Session Isolation (`COMMITTED`).

## Approved scope

- Session-scoped create, list, read, and rename project operations.
- A minimal dashboard and project workspace shell.
- Required project name and original sourcing request captured at creation.
- Presentation-only five-stage workspace navigation with Brief active and later
  stages shown as static unavailable placeholders.
- Backend, frontend, and browser coverage for the project flow and isolation.

## Explicitly out of scope

- Brief records, AI analysis, requirements, project notes, workflow progression,
  supplier/quote/comparison/decision data, and migrations.
- Generalized blocked-stage, prerequisite, next-action, or stage-transition
  workflow logic.
- Shared API clients, shared error abstractions, reusable infrastructure, or
  other work owned by M0-U6.

## Approved implementation plan

1. Add a focused project application service that creates projects for a
   resolved session; lists that session's projects newest first; and reads or
   renames only its projects.
2. Add `POST /projects`, `GET /projects`, `GET /projects/{project_id}`, and
   `PATCH /projects/{project_id}`. Creation accepts required trimmed `name`
   and `original_request`; project responses expose `id`, `name`,
   `original_request`, `stage`, `created_at`, and `updated_at`. Missing or
   expired sessions are rejected before access; nonexistent and foreign project
   IDs return the same not-found response.
3. Turn the existing session initializer into a small readiness gate used by
   the dashboard and workspace, without introducing a shared API abstraction.
4. Replace the landing placeholder with a dashboard that creates projects,
   lists current-session projects, and opens them. Add a project workspace with
   the stored request, an inline rename control, and the static five-stage
   shell.
5. Add focused backend, frontend, and browser coverage. Run repository quality
   checks. Evals are not applicable because this unit adds no AI capability.

## Review findings

### M0-U4-R1 — Name length was enforced before trimming (resolved 2026-09-22)

`CreateProjectRequest` and `RenameProjectRequest` previously applied Pydantic's
255-character constraint before stripping surrounding whitespace. A name that
trimmed to the permitted 255 characters could therefore be rejected. Both
request models now trim in pre-validation, preserving the existing required,
nonblank validation and enforcing the limit against the persisted name.

Regression coverage verifies acceptance at exactly 255 trimmed characters and
rejection above 255 for both project creation and rename.

### M0-U4-R2 — Pre-validation trimming raised on non-string input (resolved 2026-09-22)

The pre-validation trimming validators for create `name`, create
`original_request`, and rename `name` called `.strip()` before Pydantic could
type-check raw input. They now return non-string values unchanged so Pydantic
emits its normal request-validation 422 response, while strings retain the
existing trim-before-blank-and-length behavior.

API regression coverage verifies that numeric, array, object, and null values
are rejected with 422 for both create fields and the rename name field.
