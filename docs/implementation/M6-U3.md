## Approved implementation scope



### 1. Bound request bodies using existing middleware



- Extend the existing request-body middleware; do not add a parallel framework or duplicate buffering layer.

- Preserve the upload ceiling of configured PDF file bytes plus 65,536 bytes of multipart overhead, file/page checks and existing upload error codes.

- Add positive-integer environment configuration `API_MAX_REQUEST_BYTES`, default **1,000,000 bytes**, for other HTTP request bodies.

- Bound actual received bytes before parsing, including absent or understated Content-Length. Reject oversized declared lengths immediately.

- Preserve accepted request bytes, legitimate request behavior, disconnect handling and safe body replay. Bound trailing-slash upload requests consistently with canonical upload routes.

- For the newly bounded non-upload case, return the existing error envelope with HTTP 413, code `REQUEST_TOO_LARGE` and a fixed safe message. Preserve existing error contracts elsewhere.

- No counters, quotas, rate-limiting infrastructure or new service.



### 2. Remove sensitive PDF exception logging



- Replace raw exception-chain logging in upload cleanup, uncertain commits and background failure-status persistence with fixed event messages and application-generated identifiers.

- Exclude exception messages, tracebacks, SQL parameters, credentials and document text from these diagnostics.

- Preserve rollback, cleanup, retained-object handling, failure persistence and stale-attempt guards exactly. Keep safe identifiers useful for investigation.



### 3. Sanitize application-authored AI repair instructions



- Replace interpolation of `error.errors()` and exception strings in shared structured-operation and Analyst repair instructions with fixed application-authored feedback distinguishing schema failure from semantic validation failure.

- Do not promote rejected values, arbitrary field names or exception text into privileged instructions.

- Preserve existing lower-trust rejected-output handling, including comparison retry output retained as data. Do not move it into instructions.

- Preserve schemas, deterministic validators, retry/repair budgets, tool limits, scope checks and all human approval boundaries.

- Increment affected capability prompt versions to identify the security change. Do not tune substantive prompts, relax validators, alter scoring or rewrite historical baselines.

### Incremental changes

- Removed the external `/api/:path*` rewrite from `apps/web/next.config.ts` and added
  the Node-runtime `apps/web/app/api/[[...path]]/route.ts` handler. The optional catch-all

  encoding is requested. If fetch decodes a supported compressed response, stale
  encoding/length headers are removed; unsupported encodings are retained.
- Transport exceptions produce the existing generic HTTP 500 transport response and
  a fixed diagnostic, without raw exception content. Backend HTTP failures are relayed
  unchanged, including safe 401/404/413/422/503 responses.
