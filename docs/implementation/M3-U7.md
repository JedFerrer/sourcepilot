# M3-U7 — Lightweight Background Quote Processing

## Status

`PLANNING` → `PLAN_APPROVED` (human approval in this chat, 2026-09-27) → `IMPLEMENTING` → `IN_REVIEW` → `QA` → `READY_TO_COMMIT` → `COMMITTED`.

## Objective

Connect PDF upload to the existing parser and M3-U6 QuoteExtraction capability. The upload commits PROCESSING metadata before scheduling work; a separate background session produces an unconfirmed draft or records FAILED.

## Dependencies

M3-U6 and its prerequisites are committed. The current upload stores a PDF and PROCESSING quote, but does not schedule parsing or extraction. Existing Quote and QuoteValue models can store normalized draft values and uncertainty, but not source block IDs or conflict alternatives.

## Approved implementation plan

1. At upload commit, record the first processing attempt and processing_started_at; leave processing_completed_at null. Schedule a FastAPI background task only after commit, passing only the document ID. Use a fresh worker database session and load the stored PDF and owning session. Parsing and extraction must not run inline.
2. Parse and persist blocks, invoke the existing M3-U6 QuoteExtraction contract, and map its fields to existing Quote/QuoteValue models. Known values use AI_EXTRACTED origin and matching extracted/current values. Unknown and conflicting fields have null current values; retain uncertainty where supported. Never select a conflict alternative. Do not persist source IDs, conflict alternatives, or other field evidence in U7.
3. Atomically persist the complete draft and set quote and document to NEEDS_REVIEW, including processing_completed_at. Finalize only the same still-current PROCESSING attempt. On draft persistence failure, roll back before separately recording terminal FAILED with processing_completed_at; no partial draft survives. Parser/extractor failure also records FAILED and completion time while retaining the PDF and valid persisted blocks. Interrupted work remains PROCESSING with a null completion time.
4. Extend the existing owner-scoped quote read response to expose PDF document processing status, attempt, timestamps, and safe failure state for polling. Add PDF upload and polling to the Quotes page, showing only Processing, Needs Review, and Failed. Do not add PDF correction, evidence review, confirmation, or retry controls.

## Acceptance criteria and tests

- Upload metadata is committed before scheduling; parsing/extraction is not invoked inline. Test the worker separately with a fresh session, without latency thresholds.
- Success persists a complete unconfirmed draft and completion time atomically. Unknown/conflict fields do not silently select values. A changed processing attempt cannot be finalized.
- Failure records FAILED and processing_completed_at after rollback and leaves no partial draft. Interrupted PROCESSING remains durable with processing_completed_at null.
- Owner-scoped quote polling exposes safe document metadata. Frontend upload/polling transitions, cleanup, and absence of later-unit controls are tested.
- Run relevant backend and frontend tests, type checks, lint, and Browser QA for the upload-to-Needs Review flow.

## Explicitly out of scope

M3-U8 QuoteFieldEvidence, evidence association/UI, correction and review controls; M3-U9 stale detection, retry/reprocessing, PDF confirmation and revision behavior; new queues, infrastructure, dependencies, or duplicate provenance storage. Complete extraction provenance is not preserved by U7.

## Review findings

Approved finding addressed on 2026-09-27: an in-flight poll could update Quotes after page deactivation, and an older PROCESSING response could overwrite a newer NEEDS_REVIEW or FAILED result. The polling effect now invalidates its in-flight callbacks on cleanup and applies responses only while the current quote is still PROCESSING. Focused regression tests cover deactivation with a pending request and out-of-order PROCESSING responses after both terminal states.

Fix verification from `apps/web`: focused QuoteReview tests 12 passed; full frontend suite 56 passed across 8 files; typecheck and lint passed.
