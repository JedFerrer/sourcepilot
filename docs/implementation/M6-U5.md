## Approved scope and exact documentation changes

### Root README: concise reviewer-facing overview

Expand [README.md](../../README.md) with these sections, keeping detailed procedures and technical explanations in existing linked documents:

1. **Purpose and workflow:** explain the sourcing problem, Brief → Suppliers → Quotes → Comparison → Decision, and the four human approval/review points. End at the preferred-supplier decision.
2. **Architecture:** include a compact text diagram of Next.js → FastAPI application/domain/AI modules → PostgreSQL and private PDF storage, with external model calls and optional Langfuse. Distinguish local storage from the supported S3-compatible backend; make no deployment claim.
3. **Responsibility boundaries:** use a short table separating deterministic readiness, retrieval, factual comparison, arithmetic, validation and workflow from AI interpretation/explanation and human approvals.
4. **Why one Sourcing Analyst:** explain model-directed evidence lookup, read-only project-scoped tools, default four-turn/six-tool-call limits and recoverable failure. Structured extraction calls are not additional agents.
5. **Evidence and freshness:** summarize PDF blocks, extracted/current values and origins, corrections preserving original evidence, confirmed quote precedence, and contextual differences versus genuine conflicts. Explain revision-aware supplier/comparison staleness and regeneration without implying visible version history or automatic refresh.
6. **Evaluation and tracing:** summarize six eval categories, deterministic tests/E2E versus explicit live evaluation, and exact checks versus heuristics/human review. Link the existing eval and observability guides. Explain authoritative local AIRun records and optional sanitized, best-effort Langfuse export.
7. **Run and demonstrate locally:** link directly to setup, the manual walkthrough and existing deterministic E2E instructions.
8. **Limitations and deferred evolution:** retain the synthetic-data disclaimer prominently. Cover text-extractable PDF limits, manual fallback, no automatic FX conversion, anonymous sessions, bounded background processing and the required caveats below.
9. **Architectural tradeoffs and further reading:** explain why PostgreSQL/application code suffice without LangGraph, why 15 structured supplier records do not justify a vector database, and why current processing does not require Redis/Celery. Link authoritative specifications; describe deferred capabilities as possibilities, not commitments.
