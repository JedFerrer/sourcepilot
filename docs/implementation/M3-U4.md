# M3-U4 — PDF Parsing and DocumentBlock Persistence

## Status

`PLANNING` → `PLAN_APPROVED` → `IMPLEMENTING` → `IN_REVIEW` → `READY_TO_COMMIT` (2026-09-27). The human approved the revised plan with preservation of internal text layout and explicit PDF non-execution protections. Full Flow applies.

## Objective

Extract stable, document-scoped text blocks from stored PDF quotes and persist each complete block set atomically. This is an internal parser and persistence unit.

## Dependencies

M3-U3 is committed. It supplies validated PDF storage, generated keys, a 10,000,000-byte default, a 15-page default, a 10-second child timeout, and PyMuPDF in the lockfile. The installed/locked parser version must be checked before implementation; do not upgrade it to match plan prose.

## Approved implementation plan

1. Extend local and S3 storage with a read into a private temporary snapshot using only the persisted validated key. Enforce the configured file-byte limit during streaming; verify SHA-256 before parsing the exact snapshot. Close streams and clean up on every path. Preserve the original failure when cleanup also fails.
2. Parse in a child process with the existing 10-second timeout and 15-page limit. Limit kept blocks to 5,000, each raw and normalized block to 64,000 UTF-8 bytes, total raw and normalized text to 4,000,000 UTF-8 bytes, and serialized child output to 8,000,000 bytes. Enforce limits while collecting/writing and reject excess or malformed output without truncation. Discard child stdout/stderr and use fixed failure codes; do not claim a memory sandbox.
3. Use PyMuPDF text blocks with image preservation disabled; keep text-type blocks only. Normalize Unicode to NFC, make line endings LF, and trim outer whitespace while retaining internal newlines and spacing. Discard whitespace-only blocks. Sort by finite `(y0, x0, y1, x1, extraction_index)` and number kept blocks from one per original one-based PDF page. Use `p<page>-b<block>` references and UUIDv5 based on document UUID plus reference. Repeatability is scoped to the locked PyMuPDF version and this policy. Blank pages have no blocks; mixed pages retain original numbering; no usable text produces an unsupported/no-extractable-text error.
4. Persist `DocumentBlock` with document FK and delete cascade, positive page/block checks, nonblank text, and a unique document/page/block constraint. Read metadata and extract outside the write transaction; the child has no database access. Lock the document row for write, recheck immutable key/hash, return unchanged matching rows, otherwise replace the complete set in one transaction. Rollback preserves prior committed rows and first-time failure leaves none. Overlapping calls serialize on the document row.
5. Preserve the M3-U3 upload, ownership, storage and parser-timeout protections. Treat PDF content only as data: never follow embedded external URLs or execute PDF JavaScript/scripts. Add no sandbox infrastructure.

## Acceptance criteria

- Text PDFs produce stable page/block references and persisted rows across repeated parsing.
- Blank and mixed pages are handled; image-only/whitespace-only documents fail truthfully without partial rows.
- Bounds, hash verification, timeout, child reaping, cleanup, and rollback protect stored data.
- Processing status and existing upload/API/UI behavior do not change.
