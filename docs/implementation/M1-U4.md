## Approved scope and implementation plan

1. Add session-scoped `POST /projects/{id}/brief/analyze`, `GET /projects/{id}/brief`, and `PATCH /projects/{id}/brief` using the existing API error shape. GET returns `200` with an empty editable Brief snapshot when no row exists: nullable core fields, an empty requirement list, `IN_PROGRESS` readiness, computed missing fields, and revision `0`. Empty GET creates or mutates no Brief or Requirement domain state; ordinary demo-session `last_seen_at` bookkeeping may occur during session resolution.
2. Allow Analyze only when `brief_revision == 0` and there is no meaningful saved Brief content. Return `409` before invoking the interpreter for a blocked request and create no AIRun. An extraction with no meaningful content persists nothing, leaves revision unchanged, and may be retried.
3. Keep `ExtractedBrief.attributes[]` and `requirements[]` separate at the AI boundary. Persist bounded attributes through the current `INFORMATIONAL` requirement mapping. Persist unstated requirement importance as `null`, never as Informational. Show ambiguities only with the analyze result.
4. Make `requirements.importance` nullable through a minimal Alembic migration and matching ORM validation. Keep the three existing non-null enum values; display `null` as **Not set**. Preserve existing rows.
5. Save meaningful extraction and requirements atomically and recalculate readiness. Define PATCH as a complete editable snapshot of core fields and requirements, supporting additions, edits, removals, bounded validation, and project ownership. PATCH can create a manual Brief after AI failure and clear all saved content.
6. Use one deterministic definition of meaningful Brief content for Analyze eligibility and revision/no-op behavior. Increment `brief_revision` once for each meaningful analysis or pre-approval manual change. An unchanged empty PATCH leaves revision `0`; clearing populated content increments once. Once revision exceeds `0`, Analyze stays blocked even if all content is cleared. Do not implement approval or post-approval behavior.
7. Replace the workspace Brief placeholder with editable core fields, separate presentation of informational attributes and sourcing requirements, importance controls, readiness and ordered missing-field reasons, plus loading, saving, analysis retry, and manual-entry states.

## Acceptance criteria

- Natural-language input populates an editable, persisted Brief without inventing missing facts or importance.
- Edits persist, readiness recalculates, and meaningful changes advance revision exactly once; no-ops do not.
- Analyze cannot overwrite saved content, including after content is later cleared.
- AI failure leaves the original request and Brief usable, with retry and manual editing available.
