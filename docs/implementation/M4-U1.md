# M4-U1 — Source Precedence Resolver

## Status

`COMMITTED` — Review and Done Check passed; the unit-scoped commit succeeded.

## Objective

Centralize deterministic source precedence for comparison facts while retaining source context and provenance.

## Source-of-truth references

- Product Specification v0.2: §§28–29, 32–34, and 46.
- Technical Architecture v0.2: §§13.1–13.3, 15.1–15.5, and 17.4.

- Development Workflow and Coding Standards: Full Flow.

## Dependencies

M2 supplier facts and evidence and M3 confirmed quote values are implemented. M3-U9 is `COMMITTED`.

## Approved scope

- Resolve a confirmed project-specific current value before a general curated supplier value; report source unavailability if neither exists.
- Determine quote authority from `CONFIRMED` status, regardless of whether the current value originated as `AI_EXTRACTED`, `USER_CORRECTED`, or `USER_ENTERED`. Exclude unconfirmed drafts.
- Preserve selected-source references and general supplier context. Preserve original PDF/extraction provenance separately when a confirmed value was corrected, without attributing that evidence as support for the correction.
- Resolve unit price and currency as one sourced fact; do not combine a quote price with catalog currency.
- Identify `CONFLICT` only for incompatible claims about the same semantic fact in the same context. Different general and project-specific values alone do not conflict.

## Explicitly out of scope

M4-U2 requirement evaluation, currency compatibility, quantity alignment, comparison warnings, and requirement `UNKNOWN`; M4-U3 comparison snapshots and staleness; APIs, UI, AI analysis, schema changes, new dependencies, and changes to protected specifications.

## Approved implementation plan

1. Add a small pure domain resolver with typed inputs for project-specific confirmed facts and general curated facts. Return the selected value and source reference, retained contextual facts, and source-resolution unavailability distinctly from requirement-evaluation `UNKNOWN`.
2. Adapt existing quote and supplier values to the resolver without changing persistence. Quote confirmation, not `QuoteValue.current_origin`, controls eligibility. A null confirmed current value may fall back to general context when genuinely absent or unknown; retained unresolved incompatible same-context alternatives block fallback.
3. Keep unit price with its currency and do not borrow one component from another source. If a confirmed quote supplies an incomplete price/currency pair, retain that source and its missing component for M4-U2 to interpret; do not invent a currency or silently substitute the catalog pair.
4. Keep selected current values distinct from original extraction and PDF evidence. When a correction is selected, retain original evidence as provenance only. Limit conflicts to incompatible same-context claims and keep general versus project differences contextual.
5. Add focused domain and provenance regression tests. Run focused and full backend pytest, Ruff, and Pyright.

## Acceptance criteria

- Confirmed project-specific values override general commercial context for all three current origins; unconfirmed drafts never enter final source resolution.
- A genuinely absent or unknown null confirmed value falls back to the general value. A null value with unresolved incompatible same-context quote evidence resolves as `CONFLICT` and preserves project provenance. With neither value available, source resolution reports unavailability without manufacturing a requirement-evaluation result.
- General context and source references remain inspectable. A corrected current value does not cite its original extraction as supporting evidence.
- A confirmed 25-day project lead time resolves over a general 30–40-day lead time without `CONFLICT`; incompatible same-context claims may produce `CONFLICT`.
- Price and currency retain one source and are never mixed across quote and catalog.
