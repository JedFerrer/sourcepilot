## Implementation plan

- Add session-scoped `POST /projects/{id}/brief/approve`. Under the project lock, verify the expected Brief revision and deterministic readiness; atomically set `APPROVED`, record `approved_at`, and move the project to `SUPPLIERS`. Approval does not increment `brief_revision`.
- Repeated approval of an already-approved current revision is **idempotent**: return the current Brief without mutating state, preserving `approved_at`, `brief_revision`, and project stage `SUPPLIERS`.
- Allow post-approval edits through the existing revision-checked PATCH. A meaningful edit that remains ready increments `brief_revision` once and retains `APPROVED`, `approved_at`, and `SUPPLIERS`. An edit that becomes incomplete increments once, sets `IN_PROGRESS`, clears `approved_at`, and returns the stage to `BRIEF`. Reapproval returns it to `SUPPLIERS`. A no-op changes none of these values.
- Show saved Brief details and readiness before approval. Require draft edits to be saved first and preserve drafts on errors. After approval or an approval-revoking edit, trigger the workspace’s existing project GET and `setProject` synchronization path so the displayed stage follows backend state. Keep Brief editing available after approval; supplier discovery remains M2 work.
- Expose `approved_at` in the Brief response. Do not add a migration, AI behavior, supplier evaluation, or another frontend source of truth for project stage.

## Tests and acceptance

- Domain and API tests cover incomplete and stale approval, session isolation, atomic updates, meaningful edits, and no-ops. The repeated-approval API test must assert unchanged `approved_at`, `brief_revision`, and `SUPPLIERS` stage, with no state mutation.
- Assert stage transitions `BRIEF → SUPPLIERS` on approval, `SUPPLIERS → BRIEF` on an incomplete edit, and `BRIEF → SUPPLIERS` on reapproval. Assert that a ready post-approval edit stays in `SUPPLIERS` with its approval timestamp intact.
- Frontend tests and Browser QA cover approval eligibility, draft preservation, editing after approval, and project-stage refresh. Complete the Full Flow review, checks, Browser QA, and Done Check before a unit-scoped commit.

## Assumptions

- `approved_at` represents the current approval and is cleared when approval is revoked.
- The existing deterministic readiness service alone determines approval eligibility.
